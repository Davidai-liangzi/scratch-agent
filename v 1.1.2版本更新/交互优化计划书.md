## 二、需求①：生成期间解除滚动锁定

### 现状与根因

`ui/webview.html` 中所有滚动都是无条件强制到底：

- `scrollBottom()`（约 L387）——被 `typeStep()` 每拍调用（L404）；
- `appendStep()` 末尾 `window.scrollTo(0, document.body.scrollHeight)`（L353）；
- `showTyping()`（L366）、`makeMsg()`（L300）。

根因：**"是否跟随最新消息"没有状态**，每拍都无条件拉到底，用户滚轮上滑后立即被覆盖。

### 方案（纯前端，`ui/webview.html`）

1. 新增跟随状态 `var autoFollow = true;`。
2. 抽出统一滚动入口：

   ```javascript
   function scrollBottom(force) {
     if (force || autoFollow) { window.scrollTo(0, document.documentElement.scrollHeight); }
   }
   ```

3. 监听 `scroll` 事件判定是否贴底，自动回填 `autoFollow`：

   ```javascript
   var FOLLOW_GAP = 80;   // 距底部 80px 内视为"在底部"
   function isNearBottom() {
     return (window.innerHeight + window.scrollY) >=
            (document.documentElement.scrollHeight - FOLLOW_GAP);
   }
   window.addEventListener('scroll', function () { autoFollow = isNearBottom(); });
   ```

   - 程序滚动到底 → 事件触发且 `isNearBottom()=true` → `autoFollow` 保持/恢复为 `true`，跟随不误关。
   - 用户上滑 → `isNearBottom()=false` → `autoFollow=false` → 后续 `typeStep` 不再拉底，视角留在用户看的位置。

4. 用户发新消息时强制恢复跟随：`appendUser()`（L304）内 `autoFollow = true;`。

5. **「↓ 回到底部」悬浮按钮**：
   - HTML：`<button id="scroll-bottom-btn" title="回到底部">↓</button>`，`position: fixed` 右下角，默认 `display:none`。
   - 显示条件：`!isNearBottom()` 时显示（`scroll` 事件里同步切换）。
   - 点击：`window.scrollTo({top: document.documentElement.scrollHeight, behavior:'smooth'}); autoFollow = true;`。

### 改动位置

- `ui/webview.html`：新增 `autoFollow` / `isNearBottom` / 滚动监听 / 悬浮按钮样式与逻辑；`scrollBottom` 增加 `force` 参数；`appendUser` 重置跟随。

### 实现步骤

- [ ] 步骤 1：新增 `autoFollow` 状态与 `FOLLOW_GAP` 常量。
- [ ] 步骤 2：`scrollBottom(force)` 改造，全部调用点改为条件滚动。
- [ ] 步骤 3：`scroll` 监听 + `isNearBottom()` 自动回填跟随状态。
- [ ] 步骤 4：新增「↓ 回到底部」悬浮按钮（HTML + CSS + 点击逻辑 + 显隐联动）。
- [ ] 步骤 5：`appendUser` / `clearMessages` 中重置 `autoFollow` 与按钮显隐。
- [ ] 步骤 6：自检（见验收标准 1）。

## 三、需求②：取消「结束本轮」，sb3 卡片进 AI 气泡

**核心变更：每一轮 = 一次生成或修改，sb3 产出后立即自动结束本轮。**

- 生成开始/导入开始时 `replace_btn.setVisible(False)`（[gui.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/gui.py#L1850-L1851)、[L1738-L1739](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/gui.py#L1736-L1740)）；

## 五、需求④：替换素材面板支持删除图片 / 添加图片

### 现状

[ReplaceDialog](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/gui.py#L474-L533) 只能「把图片拖到某一行替换该素材」，**没有删除、没有新增**：

- 候选图片条 `_build_pending_strip`（[gui.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/gui.py#L536-L563)）只读展示；
- 表格行仅支持「替换为图片」，无删除/新增；
- core 层仅有 `list_project_assets` / `replace_asset_image`，无增删函数（[core/fractch.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/core/fractch.py#L91-L138)）。

### 方案

分两块能力，均落地：

#### A. 候选图片条（管理待用图片）

- 每张候选缩略图右上角加「×」→ 从 `self.pending_images` 移除。
- 条尾加「＋ 添加图片」按钮 → `QFileDialog.getOpenFileNames` 多选 → 走 `_prepare_user_image` 预处理 → 追加到候选条并刷新。

#### B. 工程素材本身（增删素材）

- **删除图片/素材**：表格右键菜单（或在末列加删除按钮）「删除该素材」。
  - 仅允许删除**角色**（`Stage` 背景禁止删除，删了会白屏）；
  - 删除该角色的工程目录（`work_dir/<角色名>/`）；
  - 结果记入 `self.deletions`（角色名列表）。
- **添加图片**：工具栏「＋ 新增素材」按钮 → 选图 → 弹窗选择类型「新角色 / 新背景」→ 记入 `self.additions`。
  - 新角色：新建 `<名字>/main.fractch`（含该图片的 costume 声明 + 空脚本），复制图片到 `<名字>/assets/`。
  - 新背景：向 `Stage/main.fractch` 追加一条 `backdrop` 声明并复制图片。

#### C. core 层新增 API（`core/fractch.py`）

```python
def delete_project_asset(work_dir, character) -> bool:
    """删除工程内某个角色目录（Stage 不允许删除）。"""

def add_project_asset(work_dir, image_path, name, is_backdrop=False) -> bool:
    """用本地图片新增一个角色（或背景），写入 fractch 声明并复制素材。"""
```

#### D. 应用与回滚（`gui.py _open_replace_dialog`）

按 **替换 → 删除 → 新增** 顺序执行，然后 `check + rebuild`；任一步失败复用 `_snapshot` / `_restore` 思路回滚（与 `modify_project` 一致），避免把工程改坏。

### 改动位置

- `core/fractch.py`：新增 `delete_project_asset` / `add_project_asset`。
- `gui.py`：`ReplaceDialog`（候选条增删、表格删除、新增素材按钮、结果字段 `deletions` / `additions`）；`_open_replace_dialog` 应用逻辑 + 回滚。

## 六、验收标准

1. **滚动跟随**：生成期间滚轮上滑，视角停留在用户位置不被拉回；滑回底部自动恢复跟随；右下角出现「↓ 回到底部」按钮，点击平滑回底；发新消息后恢复跟随。
2. **自动结束 + sb3 卡片**：生成/修改完成后无需任何操作即自动结束本轮；AI 气泡中出现 sb3 卡片，**点击卡片即可自动打开**（Scratch 打开对应文件）；操作栏不再有「打开生成的 .sb3」按钮；再发一条消息可在同一工程上继续修改。
3. **替换按钮时机**：sb3 生成完成（或已有 sb3 解包完成）后，「替换素材」按钮立即出现，与是否结束本轮无关。
4. **素材增删**：替换面板能删除候选图片、添加候选图片；能删除工程中的角色、能新增角色/背景素材；删除 Stage 背景被正确拦截；应用后 sb3 正常重新编译，失败自动回滚。
5. **回归**：逐字输出、跳舞省略号、停止生成、切换会话均无异常、无残留。

## 七、风险与假设

- **②流程变更**：取消等待反馈后，"多轮修改"= 多条消息，每条消息一轮。若单轮修改失败，AI 会提示换种说法，用户重发即可（不再有阻塞等待）。
- **④删除素材风险**：删除角色可能影响其它文件的引用（变量 / 广播 / 克隆），当前方案以 `fractch check` 为准，check 失败即回滚；Stage 背景一律禁止删除。
- **④新增素材**：新角色采用空脚本 + 单造型，能被 Scratch 正常打开；若需要初始逻辑，由用户后续用文字描述让 AI 补。
- **本批为纯 GUI/前端改动**（`gui.py` + `ui/webview.html` + `core/fractch.py` 新增函数），`core/llm.py` 不动。
