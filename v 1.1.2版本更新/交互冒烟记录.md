# 交互冒烟记录（A 方案）

> **一句话**：让无头验证从「只看绿旗空跑」升级到「会点、会按键」，补上此前**唯一完全没覆盖**的交互层。

## 一、为什么需要

在 A 之前，`vm-runner/run.js` 只做一件事：绿旗 → 空跑 N 秒 → 拍快照。
它**不能点击、不能按键**，所以「点下去之后才发生的逻辑」全部看不见：

- 按钮/选项点中后有没有加分、有没有消失；
- 关卡能不能推进、能不能收尾；
- 分数变量会不会变。

而这三次人工试玩发现的问题（quiz 选项白屏、story 星星够不到、tour 背景不匹配），
**没有一条是靠运行时检查发现的**——当时的运行时判据只有「报错」和「什么都没发生」。

## 二、实现

### 1. `run.js` 新增交互阶段（在空跑 N 秒之后）

```
依次点击每个「可见的原始角色」→ 点击舞台 → 按 ← → ↑ ↓ 空格（各按住 350ms 后松开）
```

- **只点可见角色**：Scratch 里隐藏的角色本来就不响应点击，点了反而会把「点不到」误判成「没反应」。
- 每次点击前把鼠标移到角色所在坐标，让 `mouse x/y`、`touching mouse-pointer` 也合理。
- 交互结束后比较**指纹**（坐标 / 朝向 / 可见性 / 大小 / 造型名 / 变量 / 列表）+ 期间有没有**新台词**。

### 2. 为什么直接调 `runtime.startHats`

无头环境没有 renderer，`mouse._pickTarget()` 永远返回舞台，所以靠
`vm.postIOData('mouse', {isDown: true})` **触发不到角色点击帽**。

因此点击走 `rt.startHats('event_whenthisspriteclicked', null, target)`——这与 scratch-vm
内部 `mouse._activateClickHats()` 是同一条路径；舞台点击走 `event_whenstageclicked`。

按键走 `vm.postIOData('keyboard', {key, isDown})`：它会 emit `KEY_PRESSED`，
由 `scratch3_event` 负责启动 `when key` 帽（含 `any`），同时让 `key pressed?` 轮询也能读到。

### 3. 快照采集时机（重要）

`targets` 快照仍然在**交互之前**采集，保持「绿旗空跑 N 秒」的原有语义。
否则点击造成的位移/显示变化会掩盖「绿旗脚本根本没生效」这类问题。
交互结果单独放在 `interaction` 字段里，两者互不干扰。

### 4. Python 侧判定

`detect_runtime_issues(result, code_text="")` 新增可选参数 `code_text`（工程里所有 `.fractch` 正文）。

只有**同时满足**以下条件才报「交互没有生效」：

| 条件 | 理由 |
|---|---|
| 代码里出现 `when clicked` 或 `when key X` | 纯动画/纯剧情项目点了不动是正常的 |
| `clickable > 0` | 一个可见角色都没有时无法判定 |
| `changed == false` | 状态、变量、台词全都没变 |

调用点：`core/project.py`（自动修复）、`test_quality_baseline.py`（基线指标）。

## 三、验证

### 单测（合成结果）

```
有 when clicked + 无反应   → 1 条   ✅
有 when clicked + 有反应   → 0 条   ✅
无交互帽子 + 无反应        → 0 条   ✅
未传 code_text             → 0 条   ✅
没有可点角色               → 0 条   ✅
旧结果没有 interaction 字段 → 0 条   ✅
```

### 真实工程（6 个交付产物，零误报）

| 用例 | 可点角色 | 有新台词 | 判定 |
|---|---|---|---|
| mole | 1 | 31 | 0 条 |
| balloon | 1 | 0（变量变了） | 0 条 |
| tour | 5 | 4 | 0 条 |
| quiz | 2 | 16 | 0 条 |
| race | 4 | 3 | 0 条 |
| story | 2 | 1 | 0 条 |

`node --check`、`compileall`、`test_fallback_vm.py` 均通过。

## 四、成本与边界

**成本**：每次运行时验证多约 6~7 秒（可见角色 × 600ms + 5 个键 × 470ms + 舞台 400ms）。
涉及 3 次修复调用时，单条用例总耗时约增加 20 秒。

**边界（明确不做）**：

- 不点隐藏角色、不点克隆体、不模拟拖拽；
- 只按 5 个常用键，不试字母键与组合键；
- 只做「**有没有反应**」的粗判定，不验证「**反应对不对**」——那需要按项目生成交互剧本，
  成本高且脆弱，暂不做。

## 五、它能抓住什么

最主要的一类：**代码里写了交互，但链路没接上**——例如
按钮被 HUD 挡住、广播发了没人接、`if playing == 1` 永远不成立、点了只改了没人读的变量。

这类问题以前只能靠人工试玩发现；现在会被自动打回修复。
