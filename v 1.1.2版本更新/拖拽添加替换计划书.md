# v1.1.2 版本更新计划书（第三批：替换素材面板交互）

> 本批做两件事：
> **功能一** —— 「替换素材（用自定义图片）」面板的**添加照片/替换照片都能拖进去自动完成**，不必再点 `＋` 按钮。
> **功能二** —— 在面板里可**重命名角色 / 背景 / 造型**，点「应用」后**同步写回原项目**。
> 已确认：拖入或改名后**仍需点「应用」**才真正改动工程；重命名覆盖**角色名 + 背景名 + 造型名**三层。

## 一、更新目标

### 功能一：拖拽添加 / 替换

| 落点 | 行为 |
|---|---|
| 拖到**表格某一行** | 替换该行素材（现有能力，保留） |
| 拖到**候选图片条 / 面板空白处** | 自动加入候选图片（代替点「＋ 添加图片」） |
| 拖到**「＋ 新增素材」区域** | 自动新增一个角色/背景（名称取文件名，类型按图片宽高比自动判定） |

三者都是**填表/入待处理列表**，最终仍需点「应用」提交，可反悔、可撤销。

### 功能二：重命名角色 / 背景 / 造型

| 层级 | 改动范围 |
|---|---|
| **角色名** | 工程目录 `work_dir/<旧名>/` → `<新名>/`，并同步该精灵的 `sprite "<名>"` 声明与**全局**精灵名引用 |
| **背景名** | Stage 的 `costume/backdrop "<旧名>" file ...` 声明 + **全局** `backdrop "<旧名>";` 切换与 `when backdrop "<旧名>"` 触发器 |
| **造型名** | 该角色文件内的 `costume "<旧名>" file ...` 声明与 `costume "<旧名>";` 切换 |

全部在点「应用」时随「替换/删除/新增」一起落到工程，并重新打包为原 `.sb3`。

## 二、功能一：拖拽添加 / 替换

### 2.1 现状

`ReplaceDialog`（[gui.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/gui.py#L474)）当前的拖放能力：

| 区域 | 现状 | 控件 |
|---|---|---|
| 表格行 | ✅ 已支持：拖图片到行 → 替换该行 | `DropTable`（[gui.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/gui.py#L261)，`setAcceptDrops(True)`） |
| 候选图片条 | ❌ 只能点「＋」按钮 | `pending_box`（普通 `QFrame`，不接受拖放） |
| 新增素材 | ❌ 只能点「＋ 新增素材」按钮 | 普通 `QPushButton`（不接受拖放） |
| 面板空白处 | ❌ 无拖放 | `QDialog` 默认不接受拖放 |

根因：只有 `DropTable` 是放置区；面板本体与其余区域都没有开启拖放接收。

### 2.2 方案

#### 2.2.1 新增可复用放置区 `DropZone`

新增一个轻量控件（放在 `DropTable` 附近）：

```python
class DropZone(QFrame):
    """接受图片文件拖放的区域：拖入时高亮，放下后发出 files_dropped(list)。"""

    files_dropped = Signal(list)

    def __init__(self, parent=None):
        super().__init__(parent)
        self.setAcceptDrops(True)

    def _image_files(self, event):
        return [u.toLocalFile() for u in event.mimeData().urls()
                if u.toLocalFile()
                and os.path.splitext(u.toLocalFile())[1].lower() in script._IMAGE_EXTS]

    def dragEnterEvent(self, event):
        if self._image_files(event):
            self.setProperty("dragover", True)      # 触发高亮
            self.style().polish(self)
            event.acceptProposedAction()

    def dragLeaveEvent(self, event):
        self.setProperty("dragover", False)
        self.style().polish(self)

    def dropEvent(self, event):
        files = self._image_files(event)
        self.setProperty("dragover", False)
        self.style().polish(self)
        if files:
            self.files_dropped.emit(files)
            event.acceptProposedAction()
```

> 需 `from PySide6.QtCore import Signal`（gui.py 已导入 QtCore 的若干项，按需补 `Signal`）。

#### 2.2.2 三个落点接线

1. **候选图片条**：`self.pending_box` 由 `QFrame` 改为 `DropZone`（样式不变），
   `files_dropped` → `_on_pending_dropped(paths)`：逐张 `_prepare_user_image` → 追加进 `self.pending_images`（去重）→ `_refresh_pending()` + `_auto_match()`。

2. **「＋ 新增素材」区域**：该按钮包进一个 `DropZone`，
   `files_dropped` → `_on_new_asset_dropped(paths)`：每张图名称取文件名 stem；类型按宽高比判定（`QImage` 的 `w/h ≥ 1.25` → 背景，否则角色）；追加进 `self.additions`；`_update_change_note()` 刷新。

3. **面板空白处**：`ReplaceDialog.__init__` 里 `self.setAcceptDrops(True)`，重写 `dragEnterEvent / dragMoveEvent / dropEvent`：仅接受图片 → 落点未被任何子控件消费时视为「加入候选图片」，复用 `_on_pending_dropped`。

#### 2.2.3 多图与反馈

- 拖到**表格行**：仅取第一张（沿用 `DropTable` 现有行为）；
- 拖到**候选条 / 空白 / 新增区**：**全部**处理；
- 悬停时放置区高亮（`dragover` 属性 + QSS）。

#### 2.2.4 撤销入口

- 候选图片：每张缩略图右上角「×」移除；
- 新增素材：`change_note` 中列出「待新增角色/背景：xxx」并附「清空新增」小按钮。

## 三、功能二：重命名角色 / 背景 / 造型

### 3.1 现状

`ReplaceDialog` 的每一行来自 `list_project_assets`（[core/fractch.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/core/fractch.py#L91)），行显示名是 `角色名 · 造型名`（Stage 行为 `背景 · 背景名`）。
目前**只能替换图片、删除角色、新增素材，没有任何改名能力**；fractch 工程里名字散落在多处，手工改名极易漏改导致白屏或引用失效。

### 3.2 改名需要同步的引用点（据 `core/prompts.py` 的语法约定）

**角色（精灵）名**——全局替换以下形态：

| 形态 | 说明 |
|---|---|
| `sprite "旧名" layer N;` | 精灵声明（旧式写法；新式工程可能没有） |
| `clone "旧名";` | 克隆指定角色 |
| `motion.pointtowards(TOWARDS: "旧名")` | 面向角色 |
| `sensing.touchingobject(TOUCHINGOBJECTMENU: "旧名")` | 碰到角色 |
| `sensing.distanceto(DISTANCETOMENU: "旧名")` | 到角色的距离 |
| `sprites["旧名"]` | 读取其它角色属性 |

**背景名**——全局替换：

| 形态 | 说明 |
|---|---|
| `costume/backdrop "旧名" file "..." center 240,180;` | Stage 声明 |
| `backdrop "旧名";` | 切换背景（可能出现在任意角色文件里） |
| `when backdrop "旧名" { ... }` | 背景切换触发器 |

**造型名**——仅在该角色自己的 `main.fractch` 内替换：

| 形态 | 说明 |
|---|---|
| `costume "旧名" file "..." center ...;` | 造型声明 |
| `costume "旧名";` | 切换造型 |

> 注意：造型名与角色名/背景名可能同名，因此**角色名与背景名的替换要按上面的精确模式（带 `sprite `/`clone ` / `sprites[...]` 等限定）**，不能对全文裸字符串 `"旧名"` 无差别替换，否则会误伤同名造型。

### 3.3 UI 设计

- **操作列**：把现有「删除」单按钮扩成两个紧凑按钮 **「改名」「删除」**（Stage 行的「改名」只开放背景名，角色名置灰）。
- 点「改名」→ 弹出 `RenameDialog`：
  - 字段一 **角色名**（仅非 Stage 行显示，预填当前角色名）——该角色**所有行同步**；
  - 字段二 **造型/背景名**（预填当前别名）——只作用于本行。
  - 确定后写入 `self.char_renames: {旧角色名: 新角色名}` 与 `self.alias_renames: {行号: 新别名}`，并**即时刷新表格显示**（在「素材」列显示 `新角色名 · 新造型名`）。
- **冲突校验**（确定前拦截并提示）：
  - 角色名：非空、不含 `\ / : * ? " < > |`、不等于 `stage`（忽略大小写）、不与现有角色重名；
  - 造型/背景名：同一 target 内不与其它造型重名。

### 3.4 core 层新增 API

```python
def rename_project_asset(work_dir, old, new, is_character) -> bool:
    """重命名角色（目录 + 全局精灵名引用）或造型/背景别名（声明 + 引用）。

    - is_character=True : work_dir/<old> -> work_dir/<new>，并按 3.2 的精灵名形态全局替换；
    - is_character=False: 别名 old -> new（背景名全局替换；造型名仅在该角色文件内替换）。
    返回是否成功（失败由调用方 check 兜底回滚）。
    """
```

需在 `core/fractch.py` 补一个「精灵名/别名替换」的正则工具，并在 [script.py](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/script.py) 的 `fractch` 导入列表里再导出 `rename_project_asset`。

### 3.5 应用顺序与回滚（`_apply_assets_bg`）

在既有「替换 → 删除 → 新增」之前插入**重命名**，整体顺序：

1. **角色重命名**（目录 + 精灵名引用）
2. **造型/背景别名重命名**
3. 替换图片
4. 删除角色
5. 新增素材
6. `check_project` → `rebuild_project`（写回原 `.sb3`）
7. 任一步失败 → **整目录回滚**（沿用现有 `_snapshot` 备份 / `shutil.copytree` 回滚机制）

冲突规则：
- **同一角色既改名又被删除** → 以**删除**为准，忽略其改名；
- 删除步骤按「**重命名后**的角色名」执行（构建 `行 → 最终角色名` 映射）。

## 六、验收标准

**功能一（拖拽）**
1. 拖图片到**表格行** → 该行「替换为图片」列填上，点「应用」后生效（回归保留）。
2. 拖图片到**候选图片条或面板空白处** → 候选条出现该图，无需点「＋」。
3. 拖图片到**「＋ 新增素材」区域** → 变更提示出现「待新增角色/背景：<文件名>」；点「应用」后工程新增该素材并重新打包，`fractch check` 通过。
4. 拖拽悬停时目标区高亮；多图拖入候选/新增区全部处理，拖到行只取第一张；非图片被忽略、无报错。
5. 拖入后**未**改动工程，直到点「应用」；点「取消」不产生任何改动。

**功能二（重命名）**
6. 改**造型名** → 点「应用」后该角色 `costume "旧"` 声明与切换全部变成新名，Scratch 打开造型名正确、无白屏。
7. 改**背景名** → 点「应用」后 Stage 声明、所有 `backdrop "旧";` 切换、`when backdrop "旧"` 触发器同步更新。
8. 改**角色名** → 点「应用」后目录改名，`sprite "旧"`、`clone "旧"`、`sprites["旧"]`、`touchingobject/pointtowards/distanceto("旧")` 等引用同步更新，打包后角色名正确。
9. 命名冲突（重名 / 叫 stage / 非法字符）在**确定时即被拦截**并提示，不写盘。
10. 同时改名 + 替换 + 删除 + 新增 → 应用后结果一致且 `check` 通过；任一步失败则整目录回滚、工程保持变更前状态。
11. 改名后的名称能在下一次打开面板时正确显示（`list_project_assets` 反映新名）。

## 七、风险与假设

- **Qt 拖放冒泡**：子控件默认不接受拖放，事件会冒泡到父 `QDialog`；`DropZone` 与 `DropTable` 优先消费自身区域，三者互不干扰。若某区域意外不触发，用 `eventFilter` 兜一层。
- **改名误伤**：造型名可能与角色/背景同名，替换必须按 3.2 的**精确模式**进行，禁止对全文裸字符串做无差别替换；改名后统一以 `fractch check` 兜底，失败即回滚。
- **类型自动判定**：宽高比只是启发式（4:3 及以上判为背景）；判定错误可「取消」重来，或用「＋ 新增素材」手工指定。
- **作用面**：功能一为纯前端交互；功能二需在 `core/fractch.py` 新增改名 API。二者都不改后端生成流程，不影响已完成的四项功能。
