# v1.2.1 素材与编排多样化落地计划

> 承接《素材多样性改造计划书》已完成的第一批改动（全量目录、造型级候选、随机抽样、最近使用轮换、大纲/编码共用选材）。
> 本计划按「先选材、再内容/编排、再扩库、再度量、再约束、最后原创角色」的顺序推进，
> 每一阶段都可以独立上线，不要求一次做完。

## 一、现状与目标

### 1.1 已完成

- 素材目录不再按题材截断，全量列出 330 个角色 / 85 张背景；
- 每个抽样角色附带造型名，支持 `@official:<造型名>`；
- 每次生成随机抽样，并用 `aassets_lib/recent_assets.json` 做最近使用轮换；
- 设计大纲与编码阶段共用同一份 `asset_block`。

### 1.2 仍需解决

| 问题 | 表现 |
|---|---|
| 同题材内仍然同质 | 随机抽样可能一次选出多个同系列/同类型角色，缺少「相关性 + 多样性」的重排 |
| 编排仍然固定 | 游览类仍是「标题 → 三选项 → 三站 → 结束」，小游戏仍偏向打地鼠 |
| 题材覆盖不足 | 商场、餐厅、校园等题材只能借用 Scratch 不相关素材 |
| 缺少多样性度量 | 目前只有人工观感，没有跨请求的量化指标 |
| 素材名幻觉 | 模型仍可能编造目录里不存在的名字，触发回炉 |
| 原创角色有限 | 只能使用官方造型，无法按 seed 生成风格统一的角色变体 |

### 1.3 目标指标

| 指标 | 现状 | 目标 |
|---|---|---|
| 同 prompt 连续 5 次生成的角色名两两 Jaccard | 0.00 ~ 0.62 | 中位数 < 0.30 |
| 同 prompt 连续 5 次的结构指纹唯一率 | 未统计（预计偏低） | ≥ 80% |
| 对话文本 Distinct-2 | 未统计 | 相比基线 +30% |
| 素材名幻觉率 | 未统计 | < 1% |
| 编译 / VM 验证通过率 | 基线 | 不下降 |
| 单次 prompt 长度增幅 | — | ≤ 20% |

## 二、总体路线

| 阶段 | 内容 | 优先级 | 依赖 | 主要文件 |
|---|---|---|---|---|
| Phase 1 | MMR + facet 重排 | P0 | 无 | `core/assets_lib.py` |
| Phase 2 | Tracery + storylets | P1 | Phase 1 | `core/storygen.py`、`core/prompts.py` |
| Phase 3 | Kenney / Superpowers 外部素材 fallback | P1 | Phase 1 | `core/assets_lib.py`、外部清单 |

## 三、Phase 1：MMR + facet 重排（P0）

### 3.1 目标

把当前的「题材内均匀随机」升级为「相关性优先、组内多样」的选材：

- 同一批候选里不要出现过多同系列、同类型、同题材素材；
- 用户明确点名的素材必须保留；
- 保持现有「最近使用轮换」逻辑。

### 3.2 设计

在 `core/assets_lib.py` 中新增：

- `_asset_meta()` / `_category_of(theme, tags)`：返回素材的 facet：

```python
{
    "theme": "动物",
    "category": "character" | "animal" | "prop" | "backdrop" | "ui",
    "series": "ipzy" / "kenney" / "",
    "animated": True / False,   # 造型数 > 1
    "tags": {"people", "dance", ...},
}
```

- `category` 先用 tags + 一张小型人工覆盖表推导，例如：
  - `people/dance` → `character`
  - `animals` → `animal`
  - `food/sports/music/fantasy` → `prop`
  - 未归类通用道具 → `prop` / `ui`
- `series` 从已知作者 tag（`_KNOWN_SERIES`）或外部素材包名推导。

- `_similarity(a, b)`：

```text
sim = 0.5 * Jaccard(tags_a, tags_b)
    + 0.3 * (series_a == series_b)
    + 0.2 * (theme_a == theme_b)
```

- `_mmr_select(pool, k, relevance, rng, lambda_=0.7)`：

```text
每轮选择：
  mmr(i) = λ * relevance(i) - (1 - λ) * max_{j ∈ selected} similarity(i, j)
  relevance(i) = 用户点名 ? 1.0
               + 题材命中 ? 0.6
               + 0.3 * 需求 tag 与素材 tag 的重合度
               - 最近使用惩罚
  λ = 0.7（相关性权重），可按阶段调整
```

- 配额约束（先满足，再放宽）：
  - 角色：至少 1 个 `character` / `animal`，同一 `series` 最多 2 个，同一 `category` 最多 2 个；
  - 背景：同一 `series` 最多 1 张；
  - 如果池子不够，逐步放宽配额，不要直接报错。

### 3.3 实现步骤

- [x] 新增 `_asset_meta` / `_category_of`、`_similarity`、`_mmr_select`。
- [x] 用 `_mmr_select` 替换 `build_prompt_asset_block` 里角色/背景的 `_pick` 调用。
- [x] 保留用户点名素材的「置顶」逻辑，并把最近使用作为 -0.25 的软惩罚。
- [x] 为 `_mmr_select` 增加 `seed` / `jitter` 参数，保证测试可复现。
- [x] 新增 `test_asset_selection.py`：同 seed 结果稳定；用户点名必选；配额与多样性约束生效。

### 3.4 验收

- 同一 prompt 连续 5 次：角色名两两 Jaccard 中位数 < 0.30；
- 候选池本身包含多类时，至少覆盖 2 个 category；同一 series 不超过 2 个；单一类别池（如太空全是道具）不强制；
- 用户点名的素材 100% 出现在选材块；
- prompt 长度相比当前增幅 ≤ 10%；
- `build_system_prompt()` 仍稳定，编译与 `test_fallback_vm.py` 不回归。

### 3.5 风险

- facet 信息不足：先只用 tags / series / theme，不要为了「颜色」引入图像分析；
- MMR 可能过度排斥同题材素材：λ 从 0.7 起步，用基线数据调参；
- 配额过硬会导致选材不贴合需求：配额只作为软约束。

## 四、Phase 2：Tracery + storylets（P1）

### 4.1 目标

解决「内容与编排单调」：不再让模型每次都写同一套「标题 → 三选项 → 三站 → 结束」，
而是从**可配置的内容原型池**里选择结构、台词和互动。

### 4.2 设计

新增 `core/storygen.py`：

- **最小 grammar expander**：支持 `#symbol#` 递归展开、列表随机选择、变量替换。
  优先内置实现（约 50~80 行），不强制新增 `tracery` 依赖；需要复杂语法时再引入。
- **storylet 数据结构**：

```python
{
    "type": "intro" | "route_choice" | "station" | "mini_game" | "quiz" | "ending",
    "weight": 1.0,
    "conditions": {"themes": [...], "min_sprites": 2},
    "template": "...",          # Tracery 语法
    "interaction": "click" | "key" | "auto" | "drag",
    "asset_slots": ["guide", "prop", "backdrop"],
}
```

- `plan_flow(theme, assets, rng)` 生成 `flow_plan`：

```json
{
  "scenes": [
    {"type": "intro", "goal": "欢迎与说明", "interaction": "click"},
    {"type": "route_choice", "goal": "选择路线", "interaction": "click"},
    {"type": "station", "goal": "讲解 + 小互动", "interaction": "key"},
    {"type": "mini_game", "goal": "收集/点击计分", "interaction": "click"},
    {"type": "ending", "goal": "结算与复位", "interaction": "auto"}
  ],
  "dialogue_seed": 12345,
  "constraints": ["first=intro", "last=ending", "max_consecutive_same_type=2"]
}
```

- 约束：
  - 第一段必须是 `intro`，最后一段必须是 `ending`；
  - 连续同类型不超过 2 段；
  - 至少出现 2 种 interaction；
  - 游览/剧情类至少 2 个 station，小游戏类至少 1 个 mini_game。

### 4.3 接入方式

- `build_user_prompt` / `build_outline_user_prompt` 增加 `flow_block`，要求大纲与编码严格按场景序列组织；
- `OUTLINE_PROMPT` 保留现有可靠性规则，只把「固定四段结构」替换为「按 flow_block 组织」；
- `_SCENE_TOUR` / `_SCENE_GAME` 从「固定剧本」降级为「结构约束 + 示例」；未命中关键词时只注入通用约束，不再同时注入两套固定剧本；
- 台词、站点名、任务描述由 Tracery 生成，编码阶段直接使用，不再让模型自由发挥。

### 4.4 实现步骤

- [x] 新建 `core/storygen.py`：grammar expander、storylet 池、`plan_flow`。
- [x] 准备 6 种场景类型 + 多套 Tracery 模板；游览最多 6 段、小游戏最多 5 段。
- [x] `build_user_prompt` / `build_outline_user_prompt` 注入 `flow_block`；大纲与编码共用同一份。
- [x] 调整 `_SCENE_TOUR` / `_SCENE_GAME` 为参考写法；未命中时只注入通用约束。
- [x] 新增 `test_storygen.py`：展开器、首尾/连续类型/interaction、结构多样性、提示词接入。

### 4.5 验收

- 同一 prompt 连续 5 次：结构指纹唯一率 ≥ 80%；
- 对话文本 Distinct-2 相比基线 +30%（需全链路生成后统计；离线先用结构指纹和模板多样性验收）；
- 编译、lint、VM 验证不回归；
- 场景流程仍然可玩、可收尾、状态变量能复位。

### 4.6 风险

- 随机编排可能破坏可玩性：用首尾约束、连续类型上限、fallback 流程兜底；
- Tracery 生成文本可能过于模板化：每个 storylet 准备多个模板，并与素材/主题变量结合；
- 不要为了多样性删掉现有可靠性规则（帽子唯一、广播有发有收、状态复位）。

## 六、Phase 4：Vendi Score / Distinct-n 度量（P1）

### 6.1 目标

把「多样性」从主观感受变成可回归的指标，防止后续改动只看单次案例。

### 6.2 设计

新增 `core/diversity.py`：

- `asset_jaccard(runs)`：跨请求角色/背景集合的两两 Jaccard；
- `vendi_score(items, similarity_fn)`：基于素材 tag / facet 的相似度矩阵，
  计算 `exp(Shannon entropy(eigenvalues))`；用纯 Python Jacobi 特征值分解，不依赖 numpy；
- `structure_fingerprint(project_files)`：从 fractch 代码提取角色、帽子类型、广播名、背景切换与 say 数量，生成稳定哈希；
- `distinct_n(texts, n=2)`：台词/描述的字符 n-gram 多样性；
- `dialogue_lines(plans)`：从 flow_plan 列表提取全部台词。

新增 `test_diversity_baseline.py`：

- 选择器层：不调用 LLM，直接对 `build_prompt_asset_block` 跑 5 次；
- 全链路层：5 个固定 prompt × 3 次生成（按需手动跑，避免 CI 产生 API 费用）；
- 输出每个指标的基线值与当前值。

### 6.3 验收

- Phase 1 后：角色 Jaccard 中位数 < 0.30；
- Phase 2 后：结构指纹唯一率 ≥ 80%，Distinct-2 +30%；
- 指标写入发布检查清单，后续改动不得明显回退。

### 6.4 风险

- Vendi Score 需要相似度定义：先用 tag/facet，不要一开始就做图像 embedding；
- 全链路测试有 LLM 成本：默认只跑选择器层，全链路作为发版前手动检查。

## 七、Phase 5：Outlines / Instructor 结构化生成（P2）

### 7.1 目标

减少「素材名编造、JSON 不合法、结构跑偏」导致的回炉。

### 7.2 设计

- 设计目标是用 Pydantic 模型描述 `AssetRef` / `Outline` / `ProjectFiles`；当前环境未安装 pydantic，实际由 `core/schemas.py` 用轻量本地校验实现：
  - `AssetRef`：`name`、`kind`、`theme`、`costumes`；
  - `Outline`：主题、玩家移动、stations、sprites、backdrops、flow；
  - `ProjectFiles`：`files[]`。
- 实际实现：`catalog_names` / `resolve_asset_name` / `normalize_asset_refs` / `normalize_outline` / `validate_outline` / `build_asset_repair_prompt`。
- 生成后先做**本地校验**：
  - 素材名是否在当前 catalog；
  - 角色名/路径是否合法；
  - 大纲的 stations 背景是否真实存在。
- 校验失败时做**定向修复**：只把错误项和候选素材发给模型，不整单重写。
- Pydantic / Instructor / Outlines 保留为可选集成；当前默认走本地 schema 校验 + `response_format=json_object`。
- 这样所有 OpenAI 兼容 provider 都能用，不新增依赖，也不会因约束解码不兼容而失败。

### 7.3 验收

- 素材名幻觉率 < 1%；
- JSON / 素材名相关的回炉轮次减少 50%（离线先验证定向修复路径；真实回炉率需全链路统计）；
- 不改变现有 provider 的兼容性（不支持约束解码时自动降级）。

### 7.4 风险

- 不同 OpenAI 兼容服务的约束解码支持不一致：必须保留降级路径；
- 本地校验先做自动修正 / warning，不直接阻塞生成，避免误伤合法输出。

### 7.5 实现步骤

- [x] 新增 `core/schemas.py`：`catalog_names`、`resolve_asset_name`、`normalize_asset_refs`、`normalize_outline`、`validate_outline`、`build_asset_repair_prompt`。
- [x] `build_scratch_project` / `modify_project` 接入素材名自动修正 + 定向修复。
- [x] `_request_outline` 接入大纲素材名修正与结构提示。
- [x] 新增 `test_schemas.py`：大小写/拼写修正、100 条引用模拟、定向修复 helper、大纲校验。
- [x] 不引入 pydantic / instructor / outlines 依赖，保持 `response_format=json_object` 兼容所有 provider。

## 八、Phase 6：LPC / DiceBear 式分层与种子角色（P2，可选）

### 8.1 目标

在官方素材之外，按 seed 生成风格统一、可复现的角色变体。

### 8.2 设计

- 借鉴 Universal LPC 的「身体 + 发型 + 衣服 + 武器 + 动作帧」分层思路；
- 借鉴 DiceBear 的 `seed + style` API：同一 seed 稳定复现，不同 seed 产生不同角色；
- 新增 `core/characters.py`（原创几何 SVG，不直接使用 LPC 素材）：
  - `compose_character(seed, style, parts)` → SVG；`character_parts` / `build_variants` / `build_manifest`；
  - 分层素材放 `assets_characters/<style>/`；
  - 生成结果由 `tools/prepare_characters.py` 落盘，运行时不需要重复渲染；
- 先做 1 个风格、12 个变体；每套包含身体、头、头发、眼睛、嘴、衣服、配饰、腿鞋等分层。

### 8.3 验收

- 同一 seed 输出完全一致；
- 一个风格至少 10 个可区分变体；
- SVG 能被 Scratch / fractch 正常打包；
- 不引入 GPL / CC-BY-SA 授权风险（LPC 只作思路参考，或单独评估）。

### 8.4 风险

- 美术质量与风格统一是主要成本；
- 像素风与 Scratch 矢量风不一致；
- 授权：LPC 为 GPL3 / CC-BY-SA3，商用集成前必须评估。

### 8.5 实现步骤

- [x] 新增 `core/characters.py`：seed + style 分层生成、`compose_character`、`build_variants`、`build_manifest`。
- [x] 新增 `tools/prepare_characters.py`，生成 12 个 SVG 到 `assets_characters/default/`。
- [x] `assets_lib` / `schemas` 接入 `character_items` / `character_asset`，catalog 增加「自定义角色」。
- [x] `resolve_official_assets` 支持种子角色解析与打包。
- [x] 新增 `test_characters.py`：复现、12 变体、SVG 合法性、catalog、打包/VM。
- [x] 视觉 QA：修复肩缝与背包棕色边，12 个角色完整无裁切。
