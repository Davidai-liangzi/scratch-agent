# v1.2.1 素材多样性改造计划书

> 本次更新聚焦「素材、内容、编排过于单调」中的**素材层**：
> 让模型真正看到官方库的完整素材与造型变化，并在多次生成之间轮换，
> 而不是每次都在同一小撮名字里选。

## 一、问题与证据

### 1.1 官方库并不小，是目录只露了一层

| 库 | 本地清单 | 上游最新（scratch-gui develop） |
|---|---:|---:|
| sprites（角色） | 330 | 339 |
| costumes（造型） | 839 | 886 |
| backdrops（背景） | 85 | 85 |
| sounds（音效） | 353 | 353 |

按可视素材算，本地约 **843 套角色造型 + 85 张背景 ≈ 928 个**，上游约 **970+ 个**。

但旧目录只做了三件事：

1. `build_theme_catalog` 只遍历 `sprites` / `backdrops`，`costumes` 和 `sounds` 一次都没进目录；
2. 每个题材只列**前 18 个角色 / 前 14 个背景**，改造前有 105 个未归类角色只报总数、不列名；
3. `@official:<角色名>` 解析时只取该角色的**第一套造型**。

结果：官方库有九百多个可视素材，模型每次能看到的只有「每题材十几个名字」，造型变体也基本用不上，用户自然感知为「素材就那几个」。

### 1.2 还有两个放大因素

- 题材归类把 `walking` / `flying` 也算进「人物」，导致 Dragon、Pico Walking 等被归到人物桶；
- 本地镜像落后上游：缺 9 个角色（Kia、Luca、Noor、Sasha、Tatiana、Taylor、Trisha、Characters 1/2）和 47 套造型，而清单源只配了 Gitee 镜像。

## 二、本次范围

**本次做：**

1. 目录全量展示，并把「角色 → 造型」信息带到提示词里；
2. 每次生成随机抽样，并用「最近使用」列表做轮换；
3. 设计大纲与编码阶段共用同一份随机选材，避免两边各选一套。

**本次不做（后续版本）：**

- 音效目录、清单源自动同步；
- 玩法原型池、编排多样化、temperature 调整。

## 三、改动内容

### 3.1 `core/assets_lib.py`

- [`build_theme_catalog`](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/core/assets_lib.py#L657-L710)
  - 默认 `sprite_limit=0` / `backdrop_limit=0`，**不再截断**，全量列出 330 个角色与 85 张背景；
  - 新增「通用/图标」桶（球、挡板、按钮、礼物、Laptop 等），排除字母块 / 发光字 / 故事字母；
  - 增加一句说明：角色名代表整套造型，具体造型名见「本次选材」，也可用 `@official:<造型名>` 单独引用。

- 新增 `_theme_pools()`
  - 把清单整理成 `{题材: {"sprites": [(角色名, [造型名...])], "backdrops": [背景名]}}`；
  - 造型名直接来自 `sprites[].json.costumes`，与 `@official:<造型名>` 的解析链路一致。

- 新增 [`build_prompt_asset_block`](file:///c:/Users/16968/PycharmProjects/WelcomeScreen/core/assets_lib.py#L572-L654)
  - 先按需求关键词推断题材，再从题材池里**随机抽样**；
  - 池子大时只取一半左右（例如人物 72 个里取 6 个），给下一次留出轮换空间；
  - 每个角色附带最多 4 个造型名，可直接用于单帧引用或动画；
  - 排除 `assets_lib/recent_assets.json` 里最近用过的 60 个素材，池子不够时才回退；
  - 用户需求里明确点名的素材优先保留；
  - 商场 / 餐厅 / 校园 / 剧情 / 游览等需求自动补一组人物候选，避免选材里只有车、货架或背景；
  - 每次额外带几个「通用/图标」素材，避免这些素材永远不出现；
  - 选中的角色名与背景名写回最近使用列表，写失败静默忽略。

- 题材归类修正
  - 「人物」桶移除 `walking` / `flying`，避免 Dragon、Pico Walking 等被误归人物；
  - 补充 `购物 / 购物中心 / 超市 / 商店 / 店铺 / 校园 / 餐厅 / 美食 / 海底 / 地鼠` 等关键词；
  - 移除 `sports` 里过于宽泛的 `game`，避免英文需求被误判成运动题材。

## 六、风险与后续

- **随机抽样可能不够贴合题材**：提示词保留「确实不合适再从完整目录补」，且用户点名的素材优先。
- **造型名是姿态帧**：提示中已说明作为同一角色的造型使用，避免模型新建一堆单帧角色。
- **最近使用文件是本地缓存**：损坏或不可写时静默忽略，不影响生成。
- **本地镜像落后上游**：本次未改清单源；后续可给 `MANIFEST_SOURCES` 增加 GitHub raw 回退并强制同步一次。
- **素材之外的单调**：编排仍受场景包固定剧本影响；玩法原型池、temperature、场景包按需注入属于下一批改动。
